# Professional Self-Assessment

## Introduction

Completing the Computer Science program has allowed me to grow from someone who understood individual programming concepts into someone who can look at a complete software system and think about how its different pieces work together. Throughout my coursework, I gained experience with software development, databases, algorithms, security, mobile applications, artificial intelligence, embedded systems, full-stack development, and reverse engineering.

Developing my ePortfolio gave me an opportunity to bring those skills together, reflect on how much I have learned, and create a professional representation of the type of software engineer I want to become.

My goal is to begin my professional career as a software engineer and continue developing my skills in areas such as backend development, databases, security, cloud computing, and reliable software systems. One of the biggest changes in my thinking throughout the program has been realizing that professional software development requires much more than writing code that works. A good solution must also be maintainable, efficient, secure, understandable to other developers, and appropriate for the people or organizations that will use it.

---

## Collaboration and Communication

Communication and collaboration have become important parts of my development as a computer science student. Software engineers rarely work completely independently, so code must be understandable to teammates, reviewers, managers, clients, and other stakeholders.

Throughout my coursework, I practiced explaining technical decisions through project documentation, journals, diagrams, code comments, presentations, and written analysis. My CS 499 code review strengthened this ability because I had to explain how an existing application worked, identify weaknesses in the design, and communicate the enhancements I planned to make.

My coursework also strengthened my ability to communicate with different types of stakeholders. A technical explanation intended for another software engineer can be different from an explanation intended for a project manager or client. Projects such as my full-stack Travlr application required me to think about both the customer-facing portion of an application and the administrative functionality behind it. Experiences like this helped me understand that software development involves balancing technical requirements with usability, business needs, reliability, and the expectations of the people who interact with a system.

---

## Data Structures and Algorithms

Data structures and algorithms were another major area of growth for me. Earlier in the program, I often focused primarily on whether my program returned the expected result. As I progressed, I began paying more attention to how information is organized and processed and whether the same problem can be solved more efficiently.

I learned to examine repeated operations, filtering logic, searching, sorting, validation, and the way a program behaves as the amount of data increases. My work with artificial intelligence also helped me see how algorithms can be used in more advanced areas such as machine learning, neural networks, and decision-making systems.

These experiences taught me that selecting an appropriate algorithm or data structure involves trade-offs between performance, complexity, readability, and maintainability.

---

## Software Engineering

Software engineering has been one of the strongest areas of my growth. Across the program, I worked with several languages and platforms, including Python, Java, C++, JavaScript, Angular, Node.js, and MongoDB.

I developed applications ranging from mobile applications and dashboards to embedded-system projects and full-stack web applications. These projects required me to debug problems, work with APIs, separate application responsibilities, create reusable components, manage application state and data, and test whether different parts of a system worked correctly together.

These experiences have helped prepare me to approach software development as a complete engineering process rather than simply writing individual pieces of code.

---

## Database Development

Database development has been especially important because modern applications depend heavily on reliable data. Through MongoDB and other database coursework, I gained experience with CRUD operations, database queries, filtering, validation, indexing, and connecting databases to user-facing applications.

I learned that database development is not simply about storing and retrieving information. Developers must also consider data integrity, performance, scalability, authentication, safe modification of records, and what can happen when unexpected or malicious data reaches the system.

---

## Security

Security is another area that has significantly influenced the way I approach software. My secure coding coursework taught me to look for problems such as buffer overflows, integer overflow and underflow, SQL injection, improper input handling, and other vulnerabilities that can occur when developers assume that data or users will always behave as expected.

I also gained experience with testing, exception handling, static analysis, and secure programming practices. Reverse engineering coursework gave me another perspective by requiring me to analyze lower-level program behavior and understand how software can be examined beyond its original source code.

These experiences helped me develop a security mindset in which I consider potential vulnerabilities during the design and development process instead of treating security as something that should only be added after an application has been completed.

---

## ePortfolio Artifact

The artifact at the center of my ePortfolio is my **Animal Shelter Dashboard**, originally developed in CS 340. I selected this project because it combines several areas of computer science within one working application, including Python programming, a Dash user interface, MongoDB, data processing, CRUD functionality, filtering, and visualization.

Using the same artifact across all three enhancement categories allows the portfolio to clearly demonstrate my development over time.

### Software Design and Engineering

For the software design and engineering enhancement, I improved the organization and reliability of the application by refactoring the CRUD functionality, strengthening validation and exception handling, making update and delete operations safer, and improving documentation and readability.

These improvements transformed the project from something that primarily demonstrated functionality into an application that better demonstrates maintainable software engineering practices.

### Algorithms and Data Structures

For the algorithms and data structures enhancement, I concentrated on how the application processed information. I reorganized repeated filtering logic into reusable, configuration-based structures, reduced unnecessary repetition, strengthened defensive validation, and improved how data was processed before it was displayed.

This enhancement demonstrates my ability to evaluate an existing solution rather than automatically accepting the first working implementation.

### Databases

The database enhancement completed the progression of the artifact. I expanded the MongoDB implementation with safer configuration, validation, indexing, pagination, aggregation, controlled updates, and protections around destructive database operations.

I also moved sensitive connection information toward environment-based configuration and added safeguards intended to preserve data integrity. Through this enhancement, I gained a stronger understanding of the balance between database performance, security, usability, and reliability.

## Professional Growth and Future Goals

Creating this ePortfolio has allowed me to see my progress in a way that individual assignments did not always make obvious. When I compare the original Animal Shelter Dashboard with the enhanced version, I can see how my thinking has changed.

I am no longer satisfied simply because an application runs successfully. I now ask whether the code can be maintained, whether the data is protected, whether operations are efficient, whether another developer can understand the system, and whether the solution can continue to work as requirements change.

As I complete my bachelor's degree and move into the software engineering field, I want to continue building on this foundation. I know that computer science will continue changing and that technologies such as artificial intelligence, cloud computing, cybersecurity, and distributed systems will continue influencing the work software engineers perform.

My education has given me the technical foundation to continue learning those technologies while also providing experience in solving problems, adapting to unfamiliar systems, and improving existing software. This ePortfolio represents both the skills I have developed so far and the foundation I plan to build upon throughout my professional career.
